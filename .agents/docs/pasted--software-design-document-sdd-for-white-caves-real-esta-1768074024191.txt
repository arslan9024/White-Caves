## **1. SYSTEM ARCHITECTURE OVERVIEW**

### **1.1 Architectural Pattern**
**Microservices with Event-Driven Architecture** designed for:
- **Scalability**: Independent scaling of service modules
- **Resilience**: Fault isolation between services
- **Flexibility**: Independent deployment of business services
- **Maintainability**: Clear separation of concerns

### **1.3 Technology Stack**

| **Layer** | **Technology** | **Justification** |
|-----------|----------------|-------------------|
| **Frontend** | React 18 + TypeScript | Component reusability, strong typing for complex UI |
| **Mobile** | React Native | Cross-platform, shared business logic |
| **API Gateway** | Kong/NGINX | Industry standard, extensible with plugins |
| **Backend Services** | Node.js + Express/Typescript | Fast development, large ecosystem, TypeScript safety |
| **Event Streaming** | Apache Kafka | High-throughput, reliable event processing |
| **Message Queue** | RabbitMQ | Reliable message delivery, dead letter queues |
| **Primary Database** | MongoDB | Flexible schema for evolving services |
| **Transactional DB** | PostgreSQL | ACID compliance for financial transactions |
| **Cache** | Redis | High-performance caching for frequently accessed data |
| **Search** | Elasticsearch | Full-text search, analytics for properties |
| **File Storage** | AWS S3 + CloudFront | Scalable, secure document storage |
| **Containerization** | Docker | Consistent deployment across environments |
| **Orchestration** | Kubernetes | Auto-scaling, self-healing, service discovery |
| **CI/CD** | GitHub Actions | Integrated with GitHub, extensive marketplace |
| **Monitoring** | Prometheus + Grafana | Metrics collection and visualization |
| **Logging** | ELK Stack (Elasticsearch, Logstash, Kibana) | Centralized logging and analysis |

### **2.1 Service Catalog Microservice**

#### **2.1.1 Component Responsibilities**
- Manage all 40+ services and 8 categories
- Handle service metadata, pricing, and eligibility rules
- Enforce service-level access controls
- Manage service packages and bundles
- Track service performance metrics

#### **5.1.3 Permission Evaluation Engine**
```typescript
class PermissionEvaluator {
  evaluateServiceAccess(
    userPermissions: PermissionSet,
    serviceRequirements: ServiceAccessRules
  ): AccessDecision {
    // Check user type eligibility
    if (!serviceRequirements.eligibleUserTypes.includes(userPermissions.userType)) {
      return { granted: false, reason: 'user_type_not_eligible' };
    }
    
    // Check tier requirement
    if (userPermissions.tier < serviceRequirements.minimumTier) {
      return { granted: false, reason: 'insufficient_tier' };
    }
    
    // Check UAE PASS requirement
    if (serviceRequirements.uaePassRequired && !userPermissions.uaePassVerified) {
      return { granted: false, reason: 'uae_pass_verification_required' };
    }
    
    // Check department restrictions (for internal staff)
    if (userPermissions.department && 
        serviceRequirements.departmentRestrictions.length > 0 &&
        !serviceRequirements.departmentRestrictions.includes(userPermissions.department)) {
      return { granted: false, reason: 'department_restricted' };
    }
    
    return { granted: true };
  }
}
```

### **6.1 UAE PASS Integration**

#### **6.1.1 Integration Architecture**
```typescript
class UAEpassIntegrationService {
  private config: UAEpassConfig;
  private httpClient: HttpClient;
  private cache: CacheService;
  
  async initiateVerification(userId: string): Promise<VerificationInitiation> {
    // Generate verification request
    const request = {
      redirect_uri: `${config.appBaseUrl}/uae-pass/callback`,
      state: this.generateStateToken(userId),
      scope: ['urn:uae:digitalid:profile:general', 'urn:uae:digitalid:profile:address']
    };
    
    // Store request in cache
    await this.cache.set(`uae_pass_request:${userId}`, request, 300);
    
    // Return authorization URL
    return {
      authorizationUrl: `${config.uaePassBaseUrl}/authorize?${this.buildQueryString(request)}`,
      requestId: request.state
    };
  }
  
  async handleCallback(code: string, state: string): Promise<VerificationResult> {
    // Retrieve original request
    const userId = this.extractUserIdFromState(state);
    const request = await this.cache.get(`uae_pass_request:${userId}`);
    
    if (!request) {
      throw new Error('Verification request expired or invalid');
    }
    
    // Exchange code for tokens
    const tokens = await this.exchangeCodeForTokens(code, request);
    
    // Get user info
    const userInfo = await this.getUserInfo(tokens.access_token);
    
    // Verify and store user info
    const verificationResult = await this.verifyAndStoreUserInfo(userId, userInfo);
    
    return verificationResult;
  }
  
  private async exchangeCodeForTokens(code: string, request: any): Promise<UAEpassTokens> {
    const tokenResponse = await this.httpClient.post(
      `${config.uaePassBaseUrl}/token`,
      {
        grant_type: 'authorization_code',
        code,
        redirect_uri: request.redirect_uri,
        client_id: config.clientId,
        client_secret: config.clientSecret
      }
    );
    
    return tokenResponse.data;
  }
}
```

```typescript
// Multi-level caching strategy
class MultiLevelCache {
  private L1: InMemoryCache; // Short-lived, per-instance
  private L2: RedisCache;    // Medium-lived, shared
  private L3: Database;      // Source of truth
  
  async getService(serviceId: string): Promise<Service> {
    // Check L1 cache
    let service = await this.L1.get(`service:${serviceId}`);
    if (service) return service;
    
    // Check L2 cache
    service = await this.L2.get(`service:${serviceId}`);
    if (service) {
      // Populate L1 cache
      await this.L1.set(`service:${serviceId}`, service, 60);
      return service;
    }
    
    // Fetch from database
    service = await this.L3.getService(serviceId);
    
    // Populate caches
    await this.L2.set(`service:${serviceId}`, service, 3600);
    await this.L1.set(`service:${serviceId}`, service, 60);
    
    return service;
  }
}
```

```yaml
              aws s3 cp /backup/*.archive s3://whitecaves-backups/mongodb/
            env:
            - name: MONGODB_USERNAME
              valueFrom:
                secretKeyRef:
                  name: mongodb-secrets
                  key: backup-username
            - name: MONGODB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: mongodb-secrets
                  key: backup-password
            volumeMounts:
            - name: backup-volume
              mountPath: /backup
          restartPolicy: OnFailure
          volumes:
          - name: backup-volume
            emptyDir: {}
```

```yaml
name: CI/CD Pipeline

    runs-on: ubuntu-latest

      run: npm run test:integration

    steps:
    - uses: actions/checkout@v3
    
    - name: Build Docker image
      run: |

        docker push registry.whitecaves.ae/${{ github.event.repository.name }}:${{ github.sha }}
        
  deploy-staging:
    needs: build
    if: github.ref == 'refs/heads/develop'
    runs-on: ubuntu-latest
    steps:
    - name: Deploy to Staging

          ${{ github.event.repository.name }}=registry.whitecaves.ae/${{ github.event.repository.name }}:${{ github.sha }} \
          -n whitecaves-staging
          
  deploy-production:
    needs: deploy-staging
    if: startsWith(github.ref, 'refs/heads/release/')
```

## **APPENDIX: TECHNICAL DECISIONS LOG**

### **Decision 1: Microservices over Monolith**
**Decision**: Use microservices architecture
**Rationale**: 
- Independent scaling of business services
- Fault isolation between components
- Team autonomy and parallel development
- Technology heterogeneity for different services

### **Decision 2: MongoDB as Primary Database**
**Decision**: Use MongoDB for most services
**Rationale**:
- Flexible schema for evolving service definitions
- Native JSON support matches our data structures
- Horizontal scalability for user data
- Rich query capabilities for service catalog

### **Decision 3: PostgreSQL for Financial Data**
**Decision**: Use PostgreSQL for transactions
**Rationale**:
- ACID compliance for financial operations
- Strong consistency requirements
- Mature relational model for transactions
- Excellent support for complex joins in reporting

### **Decision 4: Event-Driven Communication**
**Decision**: Use Apache Kafka for event streaming
**Rationale**:
- Decoupled service communication
- Event sourcing for audit trails
- Real-time analytics and monitoring
- Reliable message delivery with replay capability

### **Decision 5: Kubernetes for Orchestration**
**Decision**: Use Kubernetes for container orchestration
**Rationale**:
- Auto-scaling based on demand
- Self-healing capabilities
- Service discovery and load balancing
- Declarative configuration and GitOps
