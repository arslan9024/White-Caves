```javascript
  { "department_id": 1, "assistant_id": 1 },

db.service_ai_support.createIndex(
  { "service_id": 1, "assistant_id": 1, "support_phase": 1 },

  { "employee_id": 1, "assistant_id": 1 },

);
```

## 💡 **Schema Design Rationale**

1. **Embedded Documents for Performance**: Features within AI assistants and responsibilities within employees are embedded because they're frequently accessed together.

2. **References for Relationships**: Department assignments and service support use references to maintain data consistency and avoid duplication.

3. **Unique Business IDs**: Each document has both `_id` (MongoDB's primary key) and a bu

siness-readable ID (like `WC-DEPT-01`) for easier human reference.

4. **Computed Pattern**: Monthly transaction buckets and department statistics use the computed pattern to avoid expensive aggregations at query time.

5. **Attribute Pattern**: AI features use the attribute pattern since different features may have different technical specifications.

6. **Polymorphic Pattern**: AI assistants can have different structures based on their type while staying in the same collection.

## 💡 **Schema Design Rationale**

1. **Embedded Documents for Performance**: Features within AI assistants and responsibilities within employees are embedded because they're frequently accessed together.

2. **References for Relationships**: Department assignments and service support use references to maintain data consistency and avoid duplication.

3. **Unique Business IDs**: Each document has both `_id` (MongoDB's primary key) and a business-readable ID (like `WC-DEPT-01`) for easier human reference.

4. **Computed Pattern**: Monthly transaction buckets and department statistics use the computed pattern to avoid expensive aggregations at query time.

5. **Attribute Pattern**: AI features use the attribute pattern since different features may have different technical specifications.

6. **Polymorphic Pattern**: AI assistants can have different structures based on their type while staying in the same collection.

```javascript
// Get department statistics with employee count
db.employees.aggregate([
  {
    $group: {
      _id: "$department_id",
      employee_count: { $sum: 1 },
      active_employees: {
        $sum: { $cond: [{ $eq: ["$employment.employment_status", "active"] }, 1, 0] }
      }
    }
  },
  {
    $lookup: {
      from: "departments",
      localField: "_id",
      foreignField: "department_id",
      as: "department_info"
    }
  },
  {
    $unwind: "$department_info"
  },
  {
    $project: {
      department_name: "$department_info.name",
      employee_count: 1,
      active_employees: 1,
      director: "$department_info.director_employee_id"
    }
  }
])

// Get AI assistant usage statistics
db.employee_ai_access.aggregate([
  {
    $group: {
      _id: "$assistant_id",
      total_users: { $sum: 1 },
      admin_users: {
        $sum: { $cond: [{ $eq: ["$access_level", "admin"] }, 1, 0] }
      },
      avg_queries: { $avg: "$usage_stats.total_queries" }
    }
  },
  {
    $lookup: {
      from: "ai_assistants",
      localField: "_id",
      foreignField: "assistant_id",
      as: "assistant_info"
    }
  },
  {
    $unwind: "$assistant_info"
  },
  {
    $project: {
      assistant_name: "$assistant_info.name",
      department: "$assistant_info.department_id",
      total_users: 1,
      admin_users: 1,
      avg_queries: { $round: ["$avg_queries", 0] }
    }
  },
  {
    $sort: { total_users: -1 }
  }
```
