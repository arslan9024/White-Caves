# Wave 13: Media Upload Strategy

## 1. Overview
All property images, documents, and floorplans are uploaded directly to Cloudinary using secure signed URLs generated by the backend.

## 2. Cloudinary Upload Schema
- **Folder Structure**: `white-caves/{environment}/{entity_type}/{entity_id}/`
  - Example: `white-caves/production/properties/prop_123/`
- **File Naming**: Uses UUIDs to prevent collisions.

## 3. Image Transforms
- **Thumbnails**: `c_fill,h_200,w_300,q_auto,f_auto`
- **Gallery**: `c_scale,w_1200,q_auto,f_auto`
- **Watermark**: Adds the White Caves logo to the bottom right of gallery images.

## 4. Retention & Rollback Plan
- **Soft Deletes**: Deleting an entity in the database does not immediately delete assets in Cloudinary.
- **Orphan Sweep**: A monthly cron job scans Cloudinary for assets not linked to any database record and hard-deletes them.
- **Rollback**: If an upload succeeds but the database transaction fails, the backend triggers an immediate rollback by issuing a Cloudinary destroy command.
