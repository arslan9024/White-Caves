Here is how to implement WhatsApp with Node.js using the official Meta Cloud API to avoid future bans, along with crucial information about current library options.

### ⚠️ Important Context: The Official SDK
While the most authoritative guide from the official Meta blog is from 2022, the official WhatsApp Node.js SDK (shown in other results) is now **archived and no longer maintained**. This means there is **no current official Node.js SDK**.

**How to proceed**: You have two main paths, both of which interact directly with the official Meta Cloud API:

| Approach | Description | Key Consideration |
| :--- | :--- | :--- |
| **Direct API Calls (Recommended)** | Use `axios` or `fetch` to call Meta's Graph API directly. | Most reliable, follows official docs precisely. |
| **Unofficial SDK** | Use a maintained community SDK like `@great-detail/whatsapp`. | Can simplify code but depends on a third party. |

**Do not use** unofficial automation libraries like `whatsapp-web.js`, `Baileys`, or third-party gateways. These violate Meta's terms and will get your number banned again.

### 🚀 Implementation: Send a Message with Direct API Calls
This method uses `axios`, as shown in Meta's own guide, and is the safest choice.

1.  **Set up your project**:
    ```bash
    mkdir whatsapp-bot && cd whatsapp-bot
    npm init -y
    npm install axios dotenv
    ```

2.  **Create a `.env` file** with your credentials (get these from your Meta App Dashboard):
    ```
    ACCESS_TOKEN=YOUR_SYSTEM_USER_ACCESS_TOKEN
    PHONE_NUMBER_ID=YOUR_PHONE_NUMBER_ID
    API_VERSION=v19.0 # Use the latest stable version
    RECIPIENT_WAID=PHONE_NUMBER_OF_RECIPIENT
    ```

3.  **Create `sendMessage.js`**:
    ```javascript
    require('dotenv').config();
    const axios = require('axios');

    async function sendWhatsAppMessage() {
        const url = `https://graph.facebook.com/${process.env.API_VERSION}/${process.env.PHONE_NUMBER_ID}/messages`;

        const data = {
            messaging_product: "whatsapp",
            recipient_type: "individual",
            to: process.env.RECIPIENT_WAID,
            type: "text",
            text: { 
                "preview_url": false, 
                "body": "Hello from the official WhatsApp Cloud API!" 
            }
        };

        const config = {
            headers: {
                'Authorization': `Bearer ${process.env.ACCESS_TOKEN}`,
                'Content-Type': 'application/json'
            }
        };

        try {
            const response = await axios.post(url, data, config);
            console.log('Message sent successfully:', response.data);
        } catch (error) {
            console.error('Error sending message:', error.response?.data || error.message);
        }
    }

    sendWhatsAppMessage();
    ```

4.  **Run the script**:
    ```bash
    node sendMessage.js
    ```

### 🔄 Alternative: Using an Unofficial SDK
If you prefer an SDK structure, the `@great-detail/whatsapp` package is a maintained fork of the old official SDK.

1.  **Install the SDK**:
    ```bash
    npm install @great-detail/whatsapp
    ```

2.  **Create `sendMessageSDK.js`**:
    ```javascript
    require('dotenv').config();
    const Client = require('@great-detail/whatsapp').default; // For CommonJS

    const sdk = new Client({
      request: {
        headers: { Authorization: `Bearer ${process.env.ACCESS_TOKEN}` },
      },
    });

    async function sendMessage() {
      try {
        const message = await sdk.message.createMessage({
          phoneNumberID: process.env.PHONE_NUMBER_ID,
          to: process.env.RECIPIENT_WAID,
          type: "text",
          text: { body: "Hello from the unofficial SDK!" },
        });
        console.log('Message sent successfully:', message);
      } catch (error) {
        console.error('Error:', error);
      }
    }

    sendMessage();
    ```

### ✅ Critical Best Practices to Avoid Bans
Adhering to Meta's policies is non-negotiable:

1.  **Use Message Templates for Initial Contact**: You can only send free-form messages within a 24-hour "session" window after a user messages you. For the first contact, you **must** use a pre-approved message template.
2.  **Get Explicit Opt-In**: Only message users who have explicitly given you their phone number and consented to receive messages from you.
3.  **Respect Rate Limits**: The API has strict limits. Start slowly and monitor for errors.
4.  **Handle Opt-Outs Immediately**: If a user replies with "STOP," you must honor it and cease all communication.

### 💡 Recommendations and Next Steps
Given your history with a banned number, the **Direct API Call** method is the most transparent and safest, as it follows Meta's documented patterns exactly.

To build a full application:
*   **Receiving Messages**: You must set up a webhook endpoint (a public HTTPS URL) and subscribe to it in your Meta App Dashboard. Your server (using Express) will receive POST requests with incoming message data.
*   **Sending Templates**: Use the same API endpoint but with a `type: "template"` and the appropriate `template` object structure.

For the most up-to-date API parameters and limits, always refer to the [official Meta WhatsApp Business Platform documentation](https://developers.facebook.com/docs/whatsapp/cloud-api).
