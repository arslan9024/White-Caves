### 🤖 **AI Interface Patterns for Multi-Assistant Workflows**
The use cases require multiple AIs (e.g., Clara, Sage, Oliver) to work in concert. The chat-based model is insufficient.

1.  **The "AI Huddle"**: For Use Case 3, initiating a negotiation could trigger an **"AI Strategy Session"**. The interface shows avatar icons for Clara, Sage, and Oliver in a group. Text bubbles appear as they "discuss" lead data, market comps, and negotiation tactics, culminating in a **unified set of recommendations** for the RM.
2.  **Contextual AI Handoff**: When an RM in a property detail view clicks "Prepare Offer," the system intelligently summons **Sophia (Legal)** with the contract template and **Oliver (Negotiation)** with pricing advice in a split-panel view. The user sees the *right AI at the right time* without searching.
3.  **AI-Generated Executive Briefs**: For UHNWI clients (Use Case 1), the interface should present outputs from Zoe, Sage, and Theodora not as raw data, but as a **synthesized, scrollytelling brief**. Think interactive slides with key insights, embedded valuation models, and "What if?" scenario sliders.

### 📱 **Responsive Strategy for Enterprise Workflows**
Mobile design must support critical field actions without replicating complex desktop UIs.

*   **Agent Mobile View (Use Case 3)**: Focus on the *next action*. After a viewing, the app presents a simple form: "Log Outcome" with buttons (`Client Interested`, `Needs Follow-up`, `Not a Fit`). Choosing one triggers the next logical step (e.g., `Interested` → opens Oliver's negotiation prep screen).
*   **Owner/Manager Mobile View (Use Case 2)**: The core is the **unified inbox**. Notifications about rent payments, maintenance requests, and compliance alerts appear in a single, prioritized stream. Tapping expands the detail and offers 1-tap actions (`Approve`, `Forward to Daisy`, `Schedule`).
