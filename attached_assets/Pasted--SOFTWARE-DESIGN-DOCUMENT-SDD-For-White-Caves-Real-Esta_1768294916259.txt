### **1.2 Technology Stack**

| **Layer** | **Technology** | **Justification** |
|-----------|---------------|-------------------|
| **Frontend** | React.js + Next.js + TypeScript | Server-side rendering, SEO optimization, Dubai market requires fast load times |
| **Mobile** | React Native + Expo | Cross-platform, faster development, native performance |
| **Backend** | Node.js (Express/NestJS) + Python (FastAPI) | Node for web services, Python for AI/ML components |
| **Database** | PostgreSQL (primary), Redis (cache), Elasticsearch (search) | ACID compliance, full-text search, real-time caching |
| **AI/ML** | TensorFlow, PyTorch, Scikit-learn | Industry standard for machine learning |
| **Cloud** | AWS (EC2, RDS, S3, Lambda, SageMaker) | Global infrastructure, compliance with UAE data laws |
| **DevOps** | Docker, Kubernetes, Jenkins, GitHub Actions | Scalability, CI/CD automation |
| **APIs** | GraphQL (internal), REST (external) | Flexible data querying, standard integration |

## **2. DETAILED SYSTEM DESIGN**

### **2.1 Microservices Architecture**

#### **Service 1: User Service**
**Purpose**: Authentication, authorization, profile management
**Database**: PostgreSQL (users, roles, permissions)
**Key Endpoints**:
- `POST /api/v1/auth/register` - User registration
- `POST /api/v1/auth/uae-pass/verify` - UAE PASS verification
- `GET /api/v1/users/{id}/profile` - Get user profile
- `PUT /api/v1/users/{id}/tier` - Update user tier

**Data Model**:
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    phone VARCHAR(20),
    uae_pass_id VARCHAR(100) UNIQUE,
    tier INTEGER DEFAULT 1,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

CREATE TABLE user_permissions (
    user_id UUID REFERENCES users(id),
    permission VARCHAR(100),
    granted_at TIMESTAMP
);
```

#### **Service 2: Property Service**
**Purpose**: Property listings, search, virtual tours
**Database**: PostgreSQL (property details), Elasticsearch (search index)
**Key Endpoints**:
- `GET /api/v1/properties/search` - Advanced property search
- `GET /api/v1/properties/{id}` - Property details
- `POST /api/v1/properties/{id}/virtual-tour` - Virtual tour data
- `GET /api/v1/properties/recommendations` - AI recommendations

**Data Model**:
```sql
CREATE TABLE properties (
    id UUID PRIMARY KEY,
    title VARCHAR(255),
    property_type VARCHAR(50),
    location JSONB, -- {area: "Dubai Marina", coordinates: {lat, lng}}
    price DECIMAL(15,2),
    bedrooms INTEGER,
    bathrooms INTEGER,
    area_sqft DECIMAL(10,2),
    status VARCHAR(20), -- available, reserved, sold, rented
    created_at TIMESTAMP
);

CREATE TABLE property_media (
    property_id UUID REFERENCES properties(id),
    media_type VARCHAR(20), -- image, video, virtual_tour, floor_plan
    url VARCHAR(500),
    order_index INTEGER
);
```

#### **Service 3: Service Catalog Service**
**Purpose**: 40+ services management, booking, delivery tracking
**Database**: PostgreSQL (services, bookings, deliveries)
**Key Endpoints**:
- `GET /api/v1/services` - List all services
- `POST /api/v1/services/{id}/book` - Book a service
- `GET /api/v1/services/bookings/{id}/status` - Check booking status
- `POST /api/v1/services/packages` - Create service package

**Data Model**:
```sql
CREATE TABLE services (
    id UUID PRIMARY KEY,
    name VARCHAR(255),
    category VARCHAR(100),
    description TEXT,
    base_price DECIMAL(10,2),
    estimated_duration_days INTEGER,
    department VARCHAR(50)
);

CREATE TABLE service_bookings (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    service_id UUID REFERENCES services(id),
    status VARCHAR(20), -- pending, confirmed, in_progress, completed
    booked_at TIMESTAMP,
    scheduled_date DATE,
    assigned_to UUID -- department staff
);
```

#### **Service 4: CRM Service**
**Purpose**: Departmental CRM, client management, workflow automation
**Database**: PostgreSQL (clients, interactions, tasks, workflows)
**Key Endpoints**:
- `GET /api/v1/crm/clients/{id}/360` - 360-degree client view
- `POST /api/v1/crm/tasks` - Create department task
- `GET /api/v1/crm/departments/{dept}/dashboard` - Department dashboard
- `POST /api/v1/crm/workflows/execute` - Execute workflow

**Data Model**:
```sql
CREATE TABLE clients (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    client_type VARCHAR(50), -- buyer, seller, tenant, landlord
    total_value DECIMAL(15,2),
    satisfaction_score DECIMAL(3,2),
    created_at TIMESTAMP
);

CREATE TABLE department_tasks (
    id UUID PRIMARY KEY,
    department VARCHAR(50),
    assigned_to UUID REFERENCES users(id),
    task_type VARCHAR(100),
    status VARCHAR(20),
    priority INTEGER,
    due_date TIMESTAMP,
    completed_at TIMESTAMP
);
```

#### **Service 5: Inventory Service**
**Purpose**: Property lifecycle management, compliance tracking
**Database**: PostgreSQL (inventory, maintenance, compliance)
**Key Endpoints**:
- `POST /api/v1/inventory/properties` - Add property to inventory
- `GET /api/v1/inventory/properties/{id}/lifecycle` - Property lifecycle
- `POST /api/v1/inventory/maintenance` - Schedule maintenance
- `GET /api/v1/inventory/compliance/reports` - Compliance reports

**Data Model**:
```sql
CREATE TABLE property_inventory (
    property_id UUID PRIMARY KEY REFERENCES properties(id),
    acquisition_date DATE,
    current_status VARCHAR(50),
    ownership_type VARCHAR(50),
    rera_registration_number VARCHAR(100),
    dld_contract_number VARCHAR(100),
    annual_maintenance_cost DECIMAL(10,2)
);

CREATE TABLE maintenance_records (
    id UUID PRIMARY KEY,
    property_id UUID REFERENCES properties(id),
    type VARCHAR(50), -- preventive, emergency, cosmetic
    scheduled_date DATE,
    completed_date DATE,
    cost DECIMAL(10,2),
    vendor_id UUID
);
```

#### **Service 6: AI Service**
**Purpose**: AI assistants, machine learning models, predictions
**Database**: PostgreSQL (AI models, training data, predictions)
**Key Endpoints**:
- `POST /api/v1/ai/assistants/{name}/query` - Query AI assistant
- `GET /api/v1/ai/models/performance` - AI model performance
- `POST /api/v1/ai/train` - Train/re-train AI model
- `GET /api/v1/ai/insights/daily` - Daily AI insights

**Data Model**:
```sql
CREATE TABLE ai_assistants (
    id UUID PRIMARY KEY,
    name VARCHAR(100),
    department VARCHAR(50),
    model_type VARCHAR(50),
    version VARCHAR(20),
    accuracy_score DECIMAL(5,4),
    last_trained_at TIMESTAMP
);

CREATE TABLE ai_predictions (
    id UUID PRIMARY KEY,
    assistant_id UUID REFERENCES ai_assistants(id),
    input_data JSONB,
    prediction_output JSONB,
    confidence DECIMAL(5,4),
    created_at TIMESTAMP
);
```

## **4. DATABASE SCHEMA DETAILS**

### **4.1 Core Entity Relationships**

```sql
-- Core Entity Relationship Diagram
CREATE TABLE users (
    id UUID PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    uae_pass_id VARCHAR(100) UNIQUE,
    user_type VARCHAR(50) NOT NULL, -- client, agent, staff, admin
    tier INTEGER DEFAULT 1,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE properties (
    id UUID PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    property_type VARCHAR(50) NOT NULL,
    location_id UUID REFERENCES locations(id),
    price DECIMAL(15,2),
    status VARCHAR(20) DEFAULT 'available',
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE services (
    id UUID PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    category VARCHAR(100),
    base_price DECIMAL(10,2),
    department VARCHAR(50),
    estimated_duration_days INTEGER
);

CREATE TABLE clients (
    id UUID PRIMARY KEY,
    user_id UUID UNIQUE REFERENCES users(id),
    client_type VARCHAR(50),
    total_transaction_value DECIMAL(15,2) DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE departments (
    id UUID PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL,
    head_id UUID REFERENCES users(id),
    kpi_metrics JSONB
);

CREATE TABLE ai_assistants (
    id UUID PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL,
    department VARCHAR(50),
    purpose TEXT,
    model_version VARCHAR(20),
    is_active BOOLEAN DEFAULT true
);

-- Relationship Tables
CREATE TABLE user_services (
    user_id UUID REFERENCES users(id),
    service_id UUID REFERENCES services(id),
    booking_status VARCHAR(20),
    booked_at TIMESTAMP,
    PRIMARY KEY (user_id, service_id, booked_at)
);

CREATE TABLE department_users (
    department_id UUID REFERENCES departments(id),
    user_id UUID REFERENCES users(id),
    role VARCHAR(50),
    PRIMARY KEY (department_id, user_id)
);

CREATE TABLE property_services (
    property_id UUID REFERENCES properties(id),
    service_id UUID REFERENCES services(id),
    recommended BOOLEAN DEFAULT false,
    PRIMARY KEY (property_id, service_id)
);

CREATE TABLE client_properties (
    client_id UUID REFERENCES clients(id),
    property_id UUID REFERENCES properties(id),
    relationship_type VARCHAR(50), -- owner, buyer, tenant, interested
    PRIMARY KEY (client_id, property_id)
);
```

```yaml
  - Tier 2 Services (CRM, Inventory): 30 minutes
  - Tier 3 Services (AI, Analytics): 2 hours
  - Tier 4 Services (Reporting, Archives): 4 hours

Recovery Point Objective (RPO):
  - User Data: 5 minutes
  - Property Data: 15 minutes
  - Transaction Data: 1 minute
  - Media Files: 1 hour

Backup Strategy:
  - Database: Continuous WAL archiving + Daily snapshots
  - Media: S3 versioning + Cross-region replication
  - Configuration: Git repository + Infrastructure as Code
  - AI Models: S3 storage + Version tagging
```

### **10.2 Multi-Region Deployment**

```
Primary Region: me-central-1 (UAE)
  - Active traffic
  - Read/write databases
  - Real-time processing

Secondary Region: eu-west-1 (Ireland)
  - Read replicas
  - Backup data
  - Disaster recovery standby

Failover Procedure:
  1. Detect regional failure (Health checks)
  2. Update DNS to secondary region
  3. Promote read replicas to primary
  4. Update application configuration
  5. Monitor failover completion
  6. Begin data synchronization back
```
