**1. Check Chat History & Respect Opt-Out Requests**
You should check both the chat history for keywords and the status of previously sent messages.
```javascript
// Add to your DailyCampaignManager class
async checkContactOptOutStatus(contactId) {
    try {
        // Method 1: Check for explicit opt-out keywords in chat history
        const chat = await this.client.getChatById(contactId);
        const messages = await chat.fetchMessages({ limit: 50 }); // Check last 50 messages

        const optOutKeywords = ['stop', 'unsubscribe', 'remove', 'do not send', 'opt-out'];
        let hasOptedOut = false;
        let optOutReason = '';

        for (const msg of messages) {
            if (msg.fromMe) continue; // Ignore messages we sent
            const bodyLower = msg.body.toLowerCase();
            
            for (const keyword of optOutKeywords) {
                if (bodyLower.includes(keyword)) {
                    hasOptedOut = true;
                    optOutReason = `User requested removal via message: "${msg.body.substring(0, 50)}..."`;
                    break;
                }
            }
            if (hasOptedOut) break;
        }

        // Method 2: Check delivery status of our last marketing message
        // Error 131050 indicates user opted out of marketing
        // You would need to track your own message send statuses
        // if (lastMarketingMessage && lastMarketingMessage.errorCode === '131050') {
        //     hasOptedOut = true;
        //     optOutReason = 'User officially opted out of marketing (Error 131050)';
        // }

        return {
            optedOut: hasOptedOut,
            reason: optOutReason,
            lastChecked: new Date().toISOString()
        };
    } catch (error) {
        console.error(`Error checking opt-out status for ${contactId}:`, error.message);
        // If we can't check, err on the side of caution - don't send
        return { optedOut: true, reason: `Error checking status: ${error.message}` };
    }
}
```
*Use this function:* Before sending in your campaign loop, call `const optOutStatus = await this.checkContactOptOutStatus(contactId);` and skip if `optedOut` is `true`.

**2. Detect Country Code and Log Nationality**
Use a library or a static mapping to convert international dialing codes to country names.
```javascript
// country-code-mapper.js
// A utility to map phone number prefixes to country names and nationality.
// Based on ISO 3166-1 alpha-2 codes.
class CountryCodeMapper {
    constructor() {
        // A subset of mappings: Key = Country Code, Value = { countryName, nationality }
        this.countryData = {
            '1': { countryName: 'United States / Canada', nationality: 'American/Canadian' },
            '44': { countryName: 'United Kingdom', nationality: 'British' },
            '91': { countryName: 'India', nationality: 'Indian' },
            '86': { countryName: 'China', nationality: 'Chinese' },
            '33': { countryName: 'France', nationality: 'French' },
            '49': { countryName: 'Germany', nationality: 'German' },
            '81': { countryName: 'Japan', nationality: 'Japanese' },
            // ... Add more from a comprehensive list like ISO 3166-1
        };
    }

    analyzeNumber(fullNumber) {
        // Remove the '+' and any non-digit characters to get the clean number
        const cleanNumber = fullNumber.replace(/\D/g, '');
        
        // Iterate through known country codes (longest first to avoid partial matches)
        const sortedCodes = Object.keys(this.countryData).sort((a, b) => b.length - a.length);
        
        for (const code of sortedCodes) {
            if (cleanNumber.startsWith(code)) {
                const data = this.countryData[code];
                return {
                    countryCode: code,
                    countryName: data.countryName,
                    nationality: data.nationality,
                    localNumber: cleanNumber.substring(code.length)
                };
            }
        }
        // Default/unknown
        return {
            countryCode: 'Unknown',
            countryName: 'Unknown',
            nationality: 'Unknown',
            localNumber: cleanNumber
        };
    }
}
```

**3. Schedule According to Local Timezone**
The best practice is to store all times in UTC internally and convert for display and scheduling.
```javascript
// local-time-scheduler.js
const moment = require('moment-timezone'); // Use moment-timezone for robust handling

class LocalTimeScheduler {
    constructor() {
        // Map country codes to primary timezones (this is a simplified example)
        this.countryToTimezone = {
            '1': 'America/New_York', // US
            '44': 'Europe/London',    // UK
            '91': 'Asia/Kolkata',     // India
            '86': 'Asia/Shanghai',    // China
            '33': 'Europe/Paris',     // France
            '49': 'Europe/Berlin',    // Germany
            '81': 'Asia/Tokyo',       // Japan
            // ... expand as needed
        };
    }

    // Determine the best send window for a contact's local time
    getOptimalSendWindow(countryCode) {
        const timezone = this.countryToTimezone[countryCode] || 'UTC';
        
        // Define "business hours" in the local timezone (e.g., 9 AM to 5 PM)
        return {
            timezone: timezone,
            startHourLocal: 9,
            endHourLocal: 17,
            // Avoid lunch hours, etc.
            excludedHours: [{ start: 12, end: 13 }] // Local lunch break
        };
    }

    // Check if "now" is a good time to send in the contact's locale
    isGoodTimeToSend(countryCode) {
        const window = this.getOptimalSendWindow(countryCode);
        const nowLocal = moment().tz(window.timezone);
        const currentHour = nowLocal.hour();
        const currentDay = nowLocal.day(); // 0 = Sunday, 1 = Monday, etc.

        // Don't send on weekends
        if (currentDay === 0 || currentDay === 6) {
            return { allowed: false, reason: 'Weekend in target locale' };
        }

        // Check if within business hours
        if (currentHour < window.startHourLocal || currentHour >= window.endHourLocal) {
            return { allowed: false, reason: 'Outside business hours in target locale' };
        }

        // Check excluded hours (e.g., lunch)
        for (const block of window.excludedHours) {
            if (currentHour >= block.start && currentHour < block.end) {
                return { allowed: false, reason: 'Local lunch break' };
            }
        }

        return { allowed: true, nextAvailable: null };
    }

    // Calculate delay until the next good send window
    calculateDelayUntilWindow(countryCode) {
        const window = this.getOptimalSendWindow(countryCode);
        const nowLocal = moment().tz(window.timezone);
        
        // If currently in a bad period, calculate when the next good period starts
        // (Simplified logic - you would expand this)
        if (nowLocal.hour() < window.startHourLocal) {
            const nextStart = moment().tz(window.timezone).startOf('day').hour(window.startHourLocal);
            return nextStart.diff(nowLocal, 'milliseconds');
        }
        // ... handle other cases (after hours, weekend)
        
        return 0; // Good to send now
    }
}

}
```

### ⚠️ Critical Risks and Final Cautions
While implementing these features improves your system's sophistication, it **significantly increases** the risk profile because:

1.  **Increased Detection Risk**: More active chat history checks and complex scheduling create patterns WhatsApp can detect as non-human.
2.  **Unofficial API Dangers**: As noted, using unofficial APIs violates WhatsApp's terms and is a primary reason for account bans.
3.  **Strict Policy Enforcement**: WhatsApp has stringent policies against unsolicited messages and uses algorithms to detect spam, which can lead to warnings, rate limits, or permanent bans.
4.  **Opt-Out Complexity**: WhatsApp's official system has a clear opt-out mechanism (Error `131050`). Trying to replicate this unofficially is error-prone and may not satisfy compliance requirements.

For any business-critical or customer-facing communication, these features should be implemented using the **official WhatsApp Business API**, which provides proper support for opt-out management, global scaling, and compliance.
