# Implementation Readiness Checklist

**Status:** Active  
**Owner:** Software Delivery Governance  
**Last Updated:** 2026-08-03  
**Purpose:** Provide a reusable checklist for deciding whether a feature, workflow, or implementation wave is ready to move forward.

This checklist is intended to complement the business operating docs, the software requirements layer, and the release-traceability template.

## 1) Scope and business intent

- [ ] The business outcome is clearly stated.
- [ ] The related business document is linked.
- [ ] The target user, department, or workflow is identified.
- [ ] The expected value or KPI impact is described.

## 2) Requirements and design clarity

- [ ] Functional or business requirements are documented.
- [ ] Acceptance criteria are explicit and testable.
- [ ] Design or implementation contract is linked.
- [ ] Dependencies and integration points are identified.

## 3) Delivery readiness

- [ ] The implementation owner is assigned.
- [ ] The work is linked to an implementation wave or planning artifact.
- [ ] Required tasks are broken into manageable units.
- [ ] Any external dependency or approval requirement is listed.

## 4) Quality and validation

- [ ] Tests or validation steps are defined.
- [ ] Typecheck, lint, or targeted validation commands are identified.
- [ ] Release or rollback considerations are captured.
- [ ] Evidence of completion can be reviewed by a second party.

## 5) Release decision

- [ ] The work is ready for implementation.
- [ ] The work is ready for review.
- [ ] The work is ready for release.
- [ ] Any remaining risk is documented and accepted.

## 6) Recommended usage

Use this checklist at the start of a wave, before implementation begins, and again before release review. It should help teams decide whether they are truly ready or whether additional clarification is still required.
