# Finance Engine Commission Ledger — Contract

- Parent issue: #1930
- Child issue: #2460
- Status: scoped documentation only (no runtime code introduced by this child issue)

## Purpose

Defines the behavioral contract for the Finance Engine Commission Ledger module, which
is responsible for recording, aggregating, and reconciling agent/broker commission
entries generated by the finance engine. This contract governs the module's public
surface so that downstream implementation issues (tracked under the parent) can be
built and reviewed against a stable, agreed-upon interface.

## Domain Model

### CommissionLedgerEntry

A single, append-only record representing one commission event.

| Field          | Type                                              | Description                                                                                |
| -------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `id`           | `string`                                          | Unique identifier (UUID) for the ledger entry.                                             |
| `dealId`       | `string`                                          | Identifier of the deal/transaction generating the commission.                              |
| `agentId`      | `string`                                          | Identifier of the agent/broker credited with the commission.                               |
| `grossAmount`  | `number`                                          | Gross commission amount before splits/deductions, in minor currency units (integer cents). |
| `netAmount`    | `number`                                          | Net commission amount payable to the agent after splits/deductions, in integer cents.      |
| `currency`     | `string`                                          | ISO 4217 currency code (e.g. `"AED"`, `"USD"`).                                            |
| `status`       | `'pending' \| 'approved' \| 'paid' \| 'reversed'` | Lifecycle state of the entry.                                                              |
| `createdAt`    | `string`                                          | ISO-8601 timestamp of entry creation.                                                      |
| `reconciledAt` | `string \| null`                                  | ISO-8601 timestamp when the entry was reconciled, or `null`.                               |

### Invariants

1. `netAmount` must never exceed `grossAmount`.
2. `grossAmount` and `netAmount` are non-negative integers (minor currency units); no
   fractional cents are permitted.
3. An entry transitions monotonically through `pending -> approved -> paid`, or from
   any non-`reversed` state to `reversed`. No other transitions are valid.
4. Once `status` is `paid` or `reversed`, the entry is immutable except for
   `reconciledAt`.
5. `reconciledAt`, when set, must be greater than or equal to `createdAt`.

## Public API Surface (for future implementation)

Future implementation modules fulfilling this contract must expose:

```ts
export interface CommissionLedgerEntry {
  id: string;
  dealId: string;
  agentId: string;
  grossAmount: number;
  netAmount: number;
  currency: string;
  status: 'pending' | 'approved' | 'paid' | 'reversed';
  createdAt: string;
  reconciledAt: string | null;
}

export interface CommissionLedger {
  recordEntry(
    entry: Omit<CommissionLedgerEntry, 'id' | 'createdAt' | 'reconciledAt' | 'status'>
  ): CommissionLedgerEntry;
  transition(id: string, nextStatus: CommissionLedgerEntry['status']): CommissionLedgerEntry;
  reconcile(id: string, reconciledAt: string): CommissionLedgerEntry;
  getEntry(id: string): CommissionLedgerEntry | undefined;
  listByAgent(agentId: string): CommissionLedgerEntry[];
}
```

Implementations must reject invalid state transitions and invariant violations by
throwing a descriptive `Error` rather than silently coercing data.
